# Миграции через Supabase CLI

Вместо ручного запуска SQL в SQL Editor миграции применяются командой `npm run db:push`.
CLI уже стоит в проекте (`npx supabase`), ничего устанавливать не нужно.

## Один раз: подключение

1. `npm run db:login` — откроет браузер, войти в Supabase.
2. `npm run db:link` — выбрать проект (или `npx supabase link --project-ref <ref>`; ref — это часть адреса проекта `https://<ref>.supabase.co`). Спросит пароль базы (Project Settings → Database).
3. **Пометить уже применённые миграции**, иначе CLI попробует выполнить их повторно. Все 25 миграций до `20261108000000` уже применены вручную:

```
npx supabase migration repair --status applied 20261031000000 20261031000001 20261031000002 20261031000003 20261031000004 20261031000005 20261031000006 20261031000007 20261031000008 20261031000009 20261101000000 20261101010000 20261101020000 20261102000000 20261102010000 20261102020000 20261103000000 20261103010000 20261103020000 20261103030000 20261104000000 20261105000000 20261106000000 20261107000000 20261108000000
```

4. `npm run db:status` — в обеих колонках (Local / Remote) должны быть все 25 версий.

## Каждый день

- Новая миграция: `npm run db:new -- название` создаёт пустой файл `supabase/migrations/ГГГГММДДЧЧММСС_название.sql`.
- Применить: `npm run db:push` (сначала показывает, что будет выполнено, и спрашивает подтверждение).
- Проверить состояние: `npm run db:status`.

Пароль базы и токен в репозиторий не попадают (токен хранится в профиле пользователя, `supabase/.temp` в `.gitignore`).
